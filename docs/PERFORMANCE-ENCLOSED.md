# 封闭院落与连续画面性能

2026-10-28。针对“整个画面一直卡”，并按用户随后提出的“屋外林地不需要，做一个关着的门”调整当前场景。

## 当前结果

屋外松林、植被和地表不再创建、下载或进入发布资源与离线缓存。南侧开口替换为 Blender 制作的关闭双扇木门，包含独立门板、横撑、斜撑、铰链、门闩、门框及门槛，保留可编辑源文件。院门有实体碰撞；旧存档或导入存档若位于原院外区域，会恢复到院内侧通道。

院内模型、原始 PBR 纹理、几何抗锯齿、太阳阴影和 AO 规格保留。本轮是功能与性能修复，不构成整个项目“以假乱真”的最终视觉验收。木门近景、院内总览、塑形与釉面反射均已检查实机截图。

## 减少重复渲染

- 3D 场景仍使用 4× MSAA 的 HDR 缓冲；默认屏幕缓冲只显示最终画面，取消其重复抗锯齿和未被采样的深度解析。
- AO 的法线、16 次采样和模糊保留，将乘色合并进最终色调映射，省去再次开启、写入和解析整屏 MSAA 颜色缓冲。曝光测量使用同样的 AO 乘色结果。
- 釉浆仍反射实际器物与缸口，按液面在屏幕上的范围裁剪反射相机，保留像素密度和 4× MSAA；同一相机、同一帧仅计算一次。2560×1600 的施釉近景中，反射目标为 1088×704，截图中仍可看到器物倒影。
- 隐藏页面暂停渲染，返回后重新建立帧时间基准。
- 取消保留每帧屏幕缓冲；PNG 导出在同一个任务里先渲染再捕获，实际下载验证通过。
- Service Worker 先缓存小体积应用入口，其他资源随真实加载请求缓存，不在游玩期间重新批量下载整个资源库。首次使用后的离线刷新已经验证。

曝光仍使用低频异步像素回读；本轮没有将其改成纯 GPU 适应算法。林地也不是改成另一套简化树木，而是按要求完全退出当前场景。

## Chrome 测量

本机 AMD Ryzen 9 8945HX、63GiB 内存、RTX 5060 Laptop GPU，Chrome 156.0.8078.48 / ANGLE D3D11，显示器 60Hz。以下为高画质，未录制视频。运行包为 `workshop-DLf4owfc.js` / `three-CkcWMcEh.js`，离线缓存版本为 `yaohuo-ac8d7555446d`。

优化前 `qa/scene-r51-baseline.json` 的有效院中视角为 41.87 FPS、P95 50.1ms；当时为同机器、同视口的无头 Chrome。最终院中每帧提交三角形由约 1777 万降为 541 万，来自移除院外物体及减少重复绘制，院内资产未减面。原始 r51 的 `forest` 样本落到碰撞地面之外，结果无效，不作为性能通过证据；后来脚本增加了地面高度检查。r52–r55 是曝光、AO、植被分组和反射诊断，部分实验已撤回，不能当作最终配置。r56 是封院初版；以 r61 的最新版画面和数据为准。

## 重现

先运行 `npm run build`，再以 `node scripts/serve.mjs --port 5191` 提供生产文件。当前服务会读取最新构建；`启动窑火.cmd` 本身不重新构建。

```powershell
$env:QA_URL='http://127.0.0.1:5191/'
$env:QA_PREFIX='scene-local'
$env:QA_HEADED='1'
node scripts/scene-performance-check.mjs

$env:QA_PREFIX='walk-local'
$env:QA_REPORT='qa/walk-local.json'
$env:QA_WIDTH='2560'
$env:QA_HEIGHT='1600'
$env:QA_QUALITIES='high'
node scripts/benchmark.mjs
```

逐个运行浏览器检查，避免同时测试争用 GPU。脚本输出原始帧时间、浏览器/GPU 信息与截图；CPU 原始 profile 存在忽略目录 `.tmp/`。美术源文件和运行模型由 Git LFS 管理。
