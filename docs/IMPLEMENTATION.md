# 窑火 · 实施记录

依据用户提供的《历史考证与项目方案》实施。本地桌面 Chrome 为主要目标；不擅自创建云服务或公开部署。

## 架构与验收

- TypeScript / Vite / Three.js，米为世界单位；GLB 为可编辑 Blender 模型的运行时格式。
- simulation 保存独立作品身份、48 环剖面、笔触、釉层、含水率、工艺历史与窑曲线。渲染不是状态来源。
- 同一院落中的取料、淘练、拉坯、阴干、利坯、青花、施釉、装窑、烧成、验收和包装。
- Rapier 固定碰撞体与角色控制器；道具支持拾取、世界坐标放置与持久化。
- IndexedDB 自动存档，带版本与输入验证；JSON 备份导入导出；成品导出 PNG 与 GLB。
- 完整循环、坏工况因果、保存恢复和浏览器可见交互分别验证。截图与实测数据保存在 qa/。

## 历史与模拟边界

场景为清代景德镇生产环节的紧凑合成空间，并非某一遗址的复原。青花采用釉下绘饰后一次高温釉烧；不把现代通行的素烧前置为必做工序。配方、热工参数与泥体塑性属于有因果关系的游戏近似，并未由真实配方试验标定。等待通过叙事时间压缩。温度仅在辅助说明中显示为模拟值。

## Git 里程碑

1. 项目规范、依赖与验收边界。
2. 可保存的工艺模拟、工坊资产与完整玩法。
3. 浏览器实测、修复、文档和可运行发布版本。

视觉目标独立验收；未获用户确认的画面不能称为已批准的写实基准。云账户、联网展厅、多人和不同朝代瓷种属于扩展，不在单机首发中假装实现。
