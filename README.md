# 窑火

一抔泥，一器一生。以清代景德镇青花工艺为线索的桌面浏览器制瓷游戏。

在同一个三维院落里自由行走，把同一件作品从原泥带到成器堂。器形由你在坯壁上的拖动产生；青花画在三维表面上；釉层、器壁、窑位和火候共同决定烧成结果。

## 打开游戏

发布包包含已经构建的 `dist/`。安装 **Node.js 22.12 或更新版本**，双击根目录的 **启动窑火.cmd**，会启动本地服务并打开 Chrome。

也可以在项目目录执行：

```powershell
node scripts/serve.mjs --open
```

默认地址为 <http://127.0.0.1:5173/>。端口被占用时，可改为 `node scripts/serve.mjs --port 5174 --open`。不要直接双击 `dist/index.html`：模型加载和存档需要 HTTP 来源。

所有游戏资源均随包提供，运行时不调用外部模型、贴图、声音或账户服务。发布版在首次完整载入后缓存本机资源，可离线刷新。存档绑定浏览器和地址端口，更换端口前请导出备份。

## 怎样玩

| 操作 | 用途 |
| --- | --- |
| W A S D / Shift / Ctrl | 行走 / 快走 / 蹲下 |
| 点击院落，移动鼠标 | 锁定视角；也可按住右键看向 |
| E | 拾取面前的工具，或进入附近工位；手持坯板时放到工位 |
| Q | 看向近处平面，把手中物品放下 |
| M / J / Esc | 工坊图 / 手艺札记 / 退出操作或浮层 |
| 工坊图中的工作区 | 沿院中通道自动引路，WASD 可随时接管 |
| 坯壁上按住并左右拖动 | 改变该高度附近的真实半径 |
| 滚轮 | 操作工位时旋转器物 |

第一件作品按屏幕左上角提示完成：

1. 原料房取泥，淘练台调水并按住揉练。
2. 辘轳开孔，拖动坯壁塑形，调节高度。碗与瓶是创作目标，不会替换成预制模型。
3. 托到阴干架，候至半干；回辘轳利坯。
4. 青花案落笔，可用细笔、竹叶、团花、水纹和弦纹。内壁与外壁分别记录。
5. 釉药间蘸釉、清足，再放架充分阴干。
6. 镇窑选择窑位、装匣、封窑。默认“师傅扶火”会帮助添柴调风；也可关掉，自行控制。
7. 自然冷却后取器，成器堂验看、命名、包纸束草、入藏。

按住“候一夜 / 候火”会加快工艺时间。开设置暂停工艺，关闭页面后也不在后台继续烧窑。拉坯提供精细调整按钮，按键可在设置中重映射。

## 保存和带走作品

- 每四秒、页面隐藏及离开时尝试保存到 IndexedDB。建议重要作品完成后再导出 JSON 备份。
- 设置中可导出、导入完整工坊。导入前会验证文件并自动下载原工坊备份；错误文件不会覆盖当前作品。
- 成器堂可导出 **GLB**：真实器形、内外壁青花贴图、材质、工艺记录均随模型保存，单位为米。
- **PNG** 留影保存实时三维画面，不含界面文字。
- 本地最多保存 100 件作品；阴干架提供 10 个位置，一窑最多装 3 件。成品区展示最近 8 件，其余可从“藏器”调出。

## 开发与复现

```powershell
npm ci
npm run dev
npm test
npm run build
npm run qa
```

Chrome 用于实机测试。QA 录像还需要 Playwright 的 FFmpeg：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tmp/playwright"
npx playwright install ffmpeg
```

`npm run benchmark` 对发布服务的 1080p 高 / 轻画质做固定路线采样；先用 `node scripts/serve.mjs --port 4173` 启动服务。`npm run package` 生成源码与可运行发布包。

| 目录 | 内容 |
| --- | --- |
| `src/simulation/` | 工艺状态、48 环剖面、笔触、釉层、烧成与存档 |
| `src/render/` | 三维工坊、器物网格、材质、双手、音效 |
| `src/physics/` | Rapier 角色碰撞、工具刚体与热窑封门 |
| `art/` | 可编辑的工坊、骨骼手部 Blender 文件 |
| `public/assets/` | 本地 GLB、PBR 贴图、来源与 SHA-256 清单 |
| `scripts/` | 资产重建、开发 QA、性能测试、本地服务与打包 |
| `qa/` | Chrome 截图、实测报告和实际游玩导出样品 |

重建模型需 Blender；运行 `blender -b --python scripts/build-workshop.py` 和 `blender -b --python scripts/build-hands.py`。运行模型使用外部 PBR 图，`.blend` 保留编辑材质；改动后必须同时重新导出 GLB。贴图可用 `python scripts/fetch-assets.py` 重新下载并生成来源校验清单。

## 范围和依据

这是可独立运行的单机版本。场景把多个历史分工压缩到同一个院落，不是某一遗址的测绘复原。青花按釉下绘饰后高温釉烧处理，不强行增加现代电动轮或必做素烧。泥料、干燥和烧窑采用有因果关系的游戏近似，没有以真实配方实验校准；双手使用约束动作，不是双手六自由度跟踪。

云账户、跨设备自动同步、多人和其他时代瓷种尚未实现。当前以桌面 Chrome 和键鼠为主；窄屏可查看菜单与引路，没有宣称完整触屏操作。

功能与视觉分别验收。实际截图和性能见 [验证记录](docs/VERIFICATION.md)，画面仍需项目所有者确认后才能作为“已批准写实基准”。更多工艺依据、资产许可见 [考证说明](docs/HISTORY.md) 与 [资产清单](docs/ASSETS.md)。
