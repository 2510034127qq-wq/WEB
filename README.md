# 窑火

一抔泥，一器一生。以清代景德镇青花工艺为线索的桌面浏览器制瓷游戏。

当前分支为 `1.1.0-preview.2` 写实重制工作版：免费 Fab / Poly Haven 资产、实拍 PBR/HDR 光照、惯性步态和工作台鼠标光标操作。最新实施、逐轮复查与未完成问题见 [写实重制记录](docs/PHOTOGRAPHIC-REVISION.md)，旧 [沉浸修订](docs/IMMERSION-REVISION.md)、[材质与光影](docs/VISUAL-REVISION.md) 保留为阶段证据。旧 `release/yaohuo-1.0.0-rc.1.zip` 不含本轮修改，当前没有新的照片级验收结论。

在同一个三维院落里自由行走，把同一件作品从原泥带到成器堂。拖动坯壁与口沿直接改变器形；展开画布与三维器物同步显示彩绘；釉层、器壁、窑位和火候共同决定烧成结果。

## 打开游戏

发布包包含已经构建的 `dist/`。安装 **Node.js 22.12 或更新版本**，双击根目录的 **启动窑火.cmd**，会启动本地服务并打开 Chrome。

也可以在项目目录执行：

```powershell
node scripts/serve.mjs --open
```

默认地址为 <http://127.0.0.1:5173/>。端口被占用时，可改为 `node scripts/serve.mjs --port 5174 --open`。不要直接双击 `dist/index.html`：模型加载和存档需要 HTTP 来源。

所有游戏资源均随包提供，运行时不调用外部模型、贴图、声音或账户服务。发布版在首次完整载入后缓存本机资源，可离线刷新。存档绑定浏览器和地址端口，更换端口前请导出备份。

## 怎样玩

走到工作台附近按 E，视角退出锁定，使用正常鼠标光标点击与拖动。游戏不显示玩家的手或手臂。Esc 离开工作台，继续行走。此次变更见 [鼠标操作修订](docs/CURSOR-CONTROLS.md)。

| 操作 | 用途 |
| --- | --- |
| W A S D / Shift / Ctrl | 行走 / 快走 / 蹲下 |
| 点击院落，移动鼠标 | 锁定视角；也可按住右键看向 |
| E | 拾取面前的工具，或进入附近工位；手持坯板时放到工位 |
| Q | 看向近处平面，把手中物品放下 |
| F | 在当前工作台托起坯板 |
| M / J / Esc | 工坊图 / 手艺札记 / 退出操作或浮层 |
| 工坊图中的工作区 | 沿院中通道自动引路，WASD 可随时接管 |
| 进入辘轳 / 空格 | 自动开孔并持续转轮 / 暂停后继续转轮 |
| 坯壁拖动 / 口沿竖向拖动 | 横向收放轮廓，上下移动接触部位 / 提拉高度；抓取后可拖出原轮廓 |
| B / Shift 拖动 / Ctrl+Z | 暂停轮转 / 抹平 / 撤回 |
| 滚轮 / Shift+滚轮 | 旋看器物（轮台为拨轮） / 绘画笔锋 |
| R | 阴干架或窑前静候，压缩时间 |

第一件作品按屏幕左上角提示完成：

1. 点击原料台实物泥堆取泥，淘练台按住泥团来回推揉；只按住不移动不会完成。点击水碗加水。
2. 进入辘轳后自动开孔并转轮。按住坯壁左右拖动塑造腹、颈、口，按住口沿上下拖动调整高度；可加单耳或双耳。碗与瓶是创作目标，不会替换成预制模型。
3. 托到阴干架，候至半干；回辘轳利坯。
4. 青花案左侧为外壁展开画布，右侧实时预览烧成色。用画笔、底色、环带、团花、水纹与文字绘饰；选中纹样后可拖动、缩放、旋转、改色、复制或撤回。滚轮旋看器物。旧存档的三维青花笔迹仍保留。
5. 抓住器物向下入釉、上提离釉；出釉后右键在圈足来回擦净，再放架充分阴干。
6. 窑前点击“装窑并开始烧制”，按住升温进入 1220–1300 ℃ 目标区间，松开保持温度。保温成熟度达到 100% 后止火冷却；过早停火或过热仍会影响成品。
7. 自然冷却后取器，成器堂验看、命名、拖纸折拢入藏。

按住 R 会加快等候时间。开设置暂停工艺，关闭页面后也不在后台继续烧窑。塑形由器壁拖动决定；彩绘面板的笔宽控件仅调整画笔。移动按键可在设置中重映射，行走晃动可关闭。

## 保存和带走作品

- 每四秒、页面隐藏及离开时尝试保存到 IndexedDB。建议重要作品完成后再导出 JSON 备份。
- 设置中可导出、导入完整工坊。导入前会验证文件并自动下载原工坊备份；错误文件不会覆盖当前作品。
- 成器堂可导出 **GLB**：真实器形、器耳、内外壁彩绘贴图、材质、工艺记录均随模型保存，单位为米。可编辑彩绘图层保存在 JSON 工坊备份里。
- **PNG** 留影保存实时三维画面，不含界面文字。
- 本地最多保存 100 件作品；阴干架提供 10 个位置，一窑最多装 3 件。成品区展示最近 8 件，其余可从“藏器”调出。

## 开发与复现

二进制模型、Blender 源文件与贴图由 Git LFS 管理。Git 克隆后先执行 `git lfs install`、`git lfs pull`；下载源代码 ZIP 可能只有 LFS 指针，不能代替完整资源。便携发布包由实际工作目录文件打包，不依赖 Git 或 LFS 服务。

```powershell
npm ci
npm run dev
npm test
npm run build
npm run qa
```

当前手势回归脚本默认使用开发服务 5190；可先运行 `npm run dev -- --port 5190`，或设置 `QA_URL` 为实际地址。`npm run qa:walk` 录制步态；`npm run qa:kiln` 检查实物窑前控件。手势回归用公开导入的工位样本，属于分工位检查。

录像参照版本使用 `node scripts/reference-craft-check.mjs`，默认连接构建后 `npm run preview -- --port 5191` 的生产预览。它以 Chrome 的真实鼠标输入检查塑形、彩绘、控温、保存和 GLB 导出，并记录 1080p 原始帧耗时；使用公开 JSON 工位样本安排测试阶段，不冒充从取泥开始的完整生产链。

`node scripts/craft-chain-check.mjs` 在空白浏览器中通过真实输入完成碗、瓶两条生产链，检查中途刷新、入釉与净足、烧成、GLB/PNG 导出和存档往返；不导入工序样本或通过隐藏接口推进状态。默认连接冻结的生产服务 5173，使用正常游戏提供的加速等候和师傅扶火。设置 `QA_PREFIX` 可保留各轮截图及 JSON，避免覆盖失败证据。静帧审查使用 `scripts/photographic-check.mjs`，与操作测试分开。

本轮完整链通过记录为 `qa/craft-chain-r19.json`。`node scripts/audit-craft-exports.mjs` 重新解码该流程实际下载的 GLB，检查结构、纹理和工艺记录；不把文件格式有效等同于视觉验收。行走录像 `qa/walk-r21-review.webm` 保留约 35.55 秒实际输入及进出供料棚的曝光变化；最新手动窑前控件记录为 `qa/kiln-r22.json`。各次检查的构建范围与未通过项见 [写实修订记录](docs/PHOTOGRAPHIC-REVISION.md)。

Chrome 用于实机测试。QA 录像还需要 Playwright 的 FFmpeg：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tmp/playwright"
npx playwright install ffmpeg
```

`npm run benchmark` 对发布服务的 1080p 高 / 轻画质做固定路线采样；先用 `node scripts/serve.mjs --port 4173` 启动服务。可用 `QA_WIDTH` / `QA_HEIGHT` 指定视口、`QA_HEADED=1` 使用可见 Chrome 窗口、`QA_URL` 指定当前服务。`npm run package` 生成源码与可运行发布包。

设置 `QA_QUALITIES=high`、`QA_SHADOW_MODES=off,on` 可在相同资产上比较太阳阴影每帧重画与缓存复用；`off` 仅禁用缓存。`qa/benchmark-r22.json` 保存本机 1080p 高画质对照和原始帧时间，不能外推为全场景或所有设备稳定帧率。当前改动未新建完成标签或正式发布包。

| 目录 | 内容 |
| --- | --- |
| `src/simulation/` | 工艺状态、48 环剖面、笔触、釉层、烧成与存档 |
| `src/render/` | 三维工坊、器物网格、材质、工位工具、音效 |
| `src/physics/` | Rapier 角色碰撞、工具刚体与热窑封门 |
| `art/` | 可编辑工坊资产及保留的历史手部源文件 |
| `public/assets/` | 本地 GLB、PBR 贴图、来源与 SHA-256 清单 |
| `scripts/` | 资产重建、开发 QA、性能测试、本地服务与打包 |
| `qa/` | Chrome 截图、实测报告和实际游玩导出样品 |

重建模型需 Blender。工坊依次执行 `build-potters-wheel.py`、`build-workshop.py`、`bake-workshop-light.py`、`bake-local-probes.py`；陶车作为独立旋转组件导出，仍参与工坊离线光照。工具为 `build-craft-tools.py`，闭合院门为 `build-closed-gate.py`。手部与林地脚本、源资产仅供历史版本复现，不进入当前游戏或离线缓存。这些文件均在 `scripts/`。最后运行 `node scripts/compress-models.mjs` 校验并压缩 GLB。`.blend` 保留可编辑材质；改动后须同步导出、烘焙与视觉复查。各 `fetch-*-surfaces.py` / `fetch-scan-assets.py` 保存可复现下载流程及来源校验清单，实木材质由 `fetch-workshop-timber.py` 下载。

## 范围和依据

这是可独立运行的单机版本。场景把多个历史分工压缩到同一个院落，不是某一遗址的测绘复原。青花按釉下绘饰后高温釉烧处理，不强行增加现代电动轮或必做素烧。泥料、干燥和烧窑采用有因果关系的游戏近似，没有以真实配方实验校准；工作台使用鼠标光标操作，不显示玩家手部。

云账户、跨设备自动同步、多人和其他时代瓷种尚未实现。当前以桌面 Chrome 和键鼠为主；窄屏可查看菜单与引路，没有宣称完整触屏操作。

功能与视觉分别验收。当前塑形、彩绘与烧制见 [录像参照改造](docs/REFERENCE-CRAFT.md)，旧版完整流程和性能见 [旧版验证记录](docs/VERIFICATION.md)，当前资产与场景画面见 [写实修订记录](docs/PHOTOGRAPHIC-REVISION.md)。林地、匣钵与釉缸的近景细节等尚未达到项目写实目标。更多工艺依据、资产许可见 [考证说明](docs/HISTORY.md)、[资产清单](docs/ASSETS.md) 与 [免费 Fab 署名](licenses/FAB-ASSETS.md)。
